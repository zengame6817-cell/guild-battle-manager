■ ギルド戦力シートの列
デフォルトは以前のTAB形式をそのままB～Hへ保存します。

B = プレイヤー名
C = 属性1
D = 戦力1
E = 属性2
F = 戦力2
G = 属性3
H = 戦力3

もし実際の本番シートが違う場合は、API_v2.2.1.gs の
APP_CONFIG.guildColumns だけ変更すれば対応できます。

■ AI解析の考え方
例の東京ディバンカー画面から、
・画面上部のプレイヤー名
・各「所持キャラカード」の個別戦力
・属性アイコン（火 / 水 / 草）
を読み、戦力の高い順に3件を返します。

「第2班 896,575」のような班合計は対象外です。
「1610万」は 16,100,000 の整数に変換して保存します。

■ 導入手順

【1】Apps Script
本番スプレッドシート
→ 拡張機能
→ Apps Script

現在のAPI.gsを、ZIP内の「API_v2.2.1.gs」で置き換えて保存します。
既存の incrementSelectedCell などのマクロファイルは消さなくてOKです。

【2】OpenAI APIキー
Apps Script左側
→ プロジェクトの設定
→ スクリプト プロパティ
→ プロパティを追加

プロパティ:
OPENAI_API_KEY

値:
自分のOpenAI APIキー

※ APIキーはGitHub / config.js / app.jsへ絶対に書かないでください。

画像解析はApps Script側からOpenAI Responses APIへ送信します。
モデルは初期値「gpt-5.6-luna」です。
変更する場合は API_v2.2.1.gs の APP_CONFIG.openAIModel を変更します。

■ スマホでの使い方
1. 下メニュー「取込」
2. 登録先ギルドを選ぶ
3. 「画像を選択」
4. 写真アプリからスクショを選ぶ（複数OK）
5. 「AI解析」
6. 読み取った名前・属性・戦力を確認
7. 間違いがあればその場で修正
8. 「スプレッドシートへ反映」

■ 新規ギルド
戦力取込
→「＋ 新規ギルド」

Lealohaシートをテンプレートとして複製し、
B2:H200の戦力データだけを空にします。

■ 削除
「データ管理」から
・メンバー1人だけ削除
・ギルドの戦力データを全削除
・ギルドシート自体を削除
が可能です。

行削除ではなくB:Hの値だけをクリアするため、
既存シートの行番号を崩しにくい仕様です。

■ 注意
GitHub Pages → Apps Scriptへの画像解析はPOST通信を使います。
ブラウザ側はpreflightを避けるため text/plain でJSONを送信しています。

もし「AI解析APIの応答を読み取れませんでした」等が出る場合は、
まず
・Apps Scriptが新バージョンでデプロイされているか
・アクセス権が今までの本番APIと同じか
・OPENAI_API_KEY が正しいか
を確認してください。


■ v2.2.1 修正
画面右下に「Failed to fetch」と出てAI解析が失敗する問題を修正しました。

原因:
GitHub PagesとApps Script Web Appは別ドメインのため、
Apps ScriptのPOSTレスポンスをブラウザから直接読み取る方式では
リダイレクト/CORSの影響でFailed to fetchになる場合があります。

修正方式:
1. 画像を no-cors POST でApps Scriptへ送信
2. Apps Script側で画像解析
3. 解析結果を一時キャッシュ
4. ブラウザがJSONP(GET)で結果だけ取得

これにより、既存のGitHub Pages + Apps Script構成のまま動作します。
