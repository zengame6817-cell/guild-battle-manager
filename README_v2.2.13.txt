ギルド対戦管理 v2.2.6 - Gemini無料枠版

【変更点】
- OpenAI APIを廃止
- 東京ディバンカーのスクショ解析を Gemini 2.5 Flash に変更
- GEMINI_API_KEY を Apps Script のスクリプトプロパティから読み込み
- GitHub側にAPIキーは保存しない
- 画像アップロード方式、手修正、ギルド登録・更新、データ管理はv2.2.2を継続

【GitHubへ上書きするファイル】
- index.html
- app.js
- config.js
- style.css

【Apps Script側】
1. Google AI Studio で Gemini APIキーを作成
2. Apps Script → プロジェクトの設定 → スクリプト プロパティ
3. 次を追加
   プロパティ: GEMINI_API_KEY
   値: 発行したGemini APIキー
4. Apps Scriptの現在のAPI.gsの中身を全削除
5. ZIP内の API_v2.2.6.gs の中身を貼り付け
6. 保存
7. デプロイ → デプロイを管理 → 編集 → 新バージョン → デプロイ

【確認】
既存WebアプリURLに ?action=ping を付ける。
次のようになればOK:
  "message":"API v2.2.6 is working"
  "aiConfigured":true

?action=aiStatus では model が gemini-2.5-flash になればOK。

【料金】
この版は Gemini 2.5 Flash のDeveloper API無料枠で動かす前提。
無料枠にはレート/利用量の上限があり、上限時は429エラーになります。
有料課金を有効にしなくても無料枠内で利用できます。

【注意】
無料枠で送信したコンテンツはGoogleの製品改善に使用される場合があります。
ゲーム画面のスクリーンショット用途を想定しています。

【ギルドデータ列】
B=名前, C=属性1, D=戦力1, E=属性2, F=戦力2, G=属性3, H=戦力3
開始行2、200行まで。


v2.2.6 変更点
- Gemini混雑時の自動再試行を追加
- 自動フォールバック: 3.5 Flash-Lite → 3.1 Flash-Lite → 3.6 Flash
- 各モデル最大2回試行
- 404 / 429 / 5xx で再試行・モデル切替
- 成功時に実際に使用したモデルと総試行回数を記録


v2.2.7 変更点
- 戦力取込画面を「万」単位表示に統一
- 例: 16,100,000 → 1610 万
- 入力欄の右側に固定で「万」を表示
- AI解析値は万未満を切り捨てて表示・保存
- スプレッドシート保存値も従来どおり 1610 / 430 / 112 の万単位
- データ管理の戦力表示にも「万」を付与


v2.2.8 変更点
- ギルド選択時に既存戦力テーブルを自動読込
- スクショ解析で名前一致メンバーを直接更新
- 新規メンバー自動追加
- 行単位の削除予定/取消
- 手修正＋変更一括保存
- 変更破棄・再読込
- AI更新行を強調表示
- 新規ギルド作成時、プルダウン用K2:K200(Z用)へ自動登録


v2.2.9 変更点
- 最大50枚のスクショを一括選択
- 1枚ずつ順番に解析するキュー方式
- 失敗画像のみ自動再投入
- 最大6巡まで自動再解析
- 待機: 10秒→20秒→40秒→80秒→120秒上限
- 進捗表示: 完了/処理中/再試行/待機/失敗
- 最終失敗分はAI解析ボタンでその分だけ再開


v2.2.10 修正
- 画像1枚の解析完了ごとに、既存メンバー行を即時更新して表示
- 50枚すべての解析完了を待たなくてもAI更新結果を確認可能
- プレイヤー名照合で半角/全角スペース差を無視
- スプレッドシートへの確定保存は従来通り「変更をまとめて保存」で実行


v2.2.11 変更点

v2.2.12 修正
